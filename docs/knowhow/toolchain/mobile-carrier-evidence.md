# 移动载具：装载、承载运动与到达分开验证

2026-09-06，依据 [送餐开发账本](../../../reports/demo006-restaurant-development.md)。

固定机械臂装到独立差速车上，是流程级服务基础版；它不能被描述为移动双臂硬件复刻。
本次复用既有 Franka 摩擦抓取与完整轨迹记录，只给车轮关节速度目标。
车身、自由脚轮与托盘组成动力学系统；没有把底盘坐标直接赋值成航点。

- 加载成功：两件指定容器各自在闭爪且末端靠近时实际抬高 >80 mm，出发前已在托盘内且松爪。
- 承载运动：以车身完整四元数把餐品位置变换到托盘局部系；行驶的每个记录帧检查边界与高度，
  不用世界坐标静态盒子判断随车容器。保守 XY 对角包围比仅检查质心更严格。
- 送达成功：底盘净位移和路径 >2 m、轮轴实际累计旋转 >15 rad、终点在 80 mm 内，
  并有连续 3 s 的已释放、低速度稳定。仅“装上车”或“某帧到达”不足。
- 没有测量轮地接触力就不报告牵引力值；轮关节运动、底盘/餐品状态及无直接推进的源码
  支持本次轮式接触搬运，但不构成轮胎滑移率标定。

首轮到达后车身仍报告约 .03 m/s 的竖直速度，并在原 120 s 预算结束时失败。
仅位置变化小不能忽略速度残差。第二轮使用 TGS 64 位置/0 速度迭代和逐迭代外力，
同阈值通过；记录组合配置的效果，不拆成未经消融的单参数因果结论。
相关官方限制与之前的独立场景经验见 [Allegro 求解器说明](../debug-solutions/allegro-mount-contact-clock.md)。

单元测试拒绝中途掉落、缺少实际抬起、车轮不转、行程不足和最后一帧稳定但之前扰动的伪成功。
运行的物理步/时钟、源快照和外部进程返回码仍由公共审计逐项检查。
