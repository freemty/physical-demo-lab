# 收银：把物理动作、传感事件与业务结果分开验证

证据：[demo002 报告](../../../reports/demo002-checkout.md)、
[轨迹重放审计](../../../reports/demo002-audit.json)，验证于 2026-09-06。

本次没有新接触故障，直接复用了流水线已验证的防休眠与摩擦抓取。值得保留的是任务契约：

- “商品已经放入箱子”不能代替“商品已扫码”。扫描事件必须来自实际观测位置连续落在
  指定扫描区，而不是因为状态机到达名为 scan 的阶段就成功。
- 位姿是真实物理状态，SKU 则是显式已知标签。把该模拟传感器写清楚，不能称为条码视觉识别。
- 扫描与计价保持不同检查：每个已知商品恰好一次、扫描有连续帧证据、单价和合计都匹配。
  缺扫、重复扫描和错误金额在单元测试中被拒绝。
- `audit_task.py` 从轨迹重新累计扫描区占用和物体运动，再验证结果；不能只转述 result.json。
  当前语义分支仅实现收银，其他任务没有分支时默认失败。

## 记录器与启动器复用

`demos/sim_runtime.py` 提供新任务的场景辅助、源码/调用快照和逐步前后状态记录；
成功谓词仍由任务自己的验证器定义。原 `conveyor_sort.py` 未重构，避免无谓改变已经验收的第一项。

`scripts/run_task.py` 在模拟器进程之外记录 `.process.json`，与全量 `.console.log`
分开保存；即使 SDK 快速退出，也能得到实际返回码。一部视频、一个 true 结果和一个
正常进程是三项独立证据。一步预算负向用例实际返回 2，独立语义审计亦为失败。

扩展共享记录器时，要检查已完成任务的实现指纹是否过期。新增任务的传感器、夹具、
控制语义和验证器需要单独写明；不要复制收银的金额/扫描判定去代表别的物理任务。
