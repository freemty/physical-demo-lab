# 传送带休眠与仿真退出：已验证的两类失败

验证日期：2026-09-05 至 09-06。完整过程见
[首次验证报告](../../../reports/bootstrap-validation.md)。下面的运行目录均相对
`/data1/ybyang/physical-demo-lab-runtime/outputs/`；对应同级 `.console.log` 保留完整日志。

## 箱子不随传送带移动

观察：`smoke-001/` 中箱子在停带时休眠，改变传送带表面速度后没有开始移动，
`result.json` 判定失败。修复在刚体箱子上设置 PhysX sleep threshold 为 0，
不重写箱子位置，也不把箱子附着到机械臂。`smoke-002/` 中箱子由真实接触搬运约 36 cm、
提起约 31 cm，并完成单物体分拣；随后三物体测试通过。修复版本为 `565e08b`。

可复用判断：表面速度已经改变但刚体没有响应时，把“是否休眠”纳入诊断；
分别检查状态记录、速度、接触、摩擦和任务时序。这里验证的是这个场景的修复，
不能推断所有传送带或接触失败都应关闭休眠。

## 物理结果成功，但运行退出失败

观察：`eval-seeds-5-9/seed-7/` 已写出物理成功结果，却在退出时挂起；日志包含
`Out of resource descriptors!`。自己的挂起进程最终被人工终止，批次记录返回码 143。
该次运行保留为失败，不因箱子已落入正确箱体而改写成成功。

另一个已观察问题是 SDK 默认快速退出可能将本应失败的运行返回为 0。
`3cbf2ed` 在结果、轨迹、事件和视频刷新后，显式调用
`app.close(wait_for_replicator=False, skip_cleanup=True, exit_code=exit_code)`，
避免 stop 回调重新进入仍存活的渲染对象，并传递真实退出码。

验证证据：`eval-seed7-retry/summary.json` 记录 seed 7 重跑物理成功且返回 0；
`exit-gate-001/` 刻意只给一步，得到 `step_budget_exhausted`、`success=false`，
启动进程实际返回 2。seed 8、9 也在修复后正常完成。

适用边界：这是每次独立进程、记录已刷新、没有待处理 Replicator writer 的退出路径。
未来若使用异步采集、录制器或长驻进程，需要重新验证清理策略。
日志中的渲染资源错误尚不能据此声称已被普遍根治。

## 后续 demo 应沿用的检查

把“任务物理结果”“日志/视频落盘”“进程正常退出”分开判断。至少保留一次确定失败的
负向用例，确认失败不会被 SDK 清理或启动器吞掉。重跑新建目录，报告中保留首次故障和
修复后的结果；不要只挑一个好看的视频当作全部证据。
