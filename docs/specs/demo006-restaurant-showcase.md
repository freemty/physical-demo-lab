# 送餐展示样板 — 视觉层与物理层分离

2026-09-06，用户指出现有画面枯燥，确认先把送餐打磨成视觉样板，再统一其他场景。
第七项几何/规格草稿保留，暂不启动；此任务不改变此前六项已完成的物理范围。

## 展示目标

木质柜台、青绿软包椅、暖色地砖与墙面、餐具/植物/简洁挂画；物体材质使用明确
的颜色、金属度与粗糙度。食物仍是原来的刚体容器，增加可识别的便当盒盖、饮品折顶与包装字样。
降低过强环境照明，保留主光与阴影，避免白色机器人和背景混成一片。
采用装餐近景、行驶全景、桌边近景三次明确镜头切换，不加速、不剪掉物理失败。

Swiss Knife Design 明确允许当前用户/参考方向覆盖默认品牌风格；本项不套网页黑白红限制。
参考覆盖仍只有既有餐厅封面，不声称取得其完整视频或材料设置。

## 实现与验证边界

保留 `restaurant.py`、`service_cart.py`、原验证器/记录器/启动器的字节。
新 `restaurant_showcase.py` 复用同一控制器，只在相机/材质/非碰撞装饰层扩展。
运行前对全部物理 schema、几何、变换、质量/驱动/摩擦与物理材质绑定做前后签名比较；
新增装饰不得附加碰撞或刚体 API。任何物理签名变化立即中止。
包装装饰随原刚体层级运动；新椅子、餐具、植物不是新增可交互对象，不能据此声称新的碰撞能力。

短预算渲染仅用于视觉检查，会正常返回任务未完成的 2；不得算送餐成功。
最终必须完成实际仿真、通过原轨迹/物理/进程审计，检查物理隔离记录、完整视频解码与三个镜头。
原始失败、旧版视频及六项验收记录不覆盖。样板另存 `outputs/restaurant-showcase/`。

材质接口依据 [OpenUSD Simple Shading](https://openusd.org/dev/tut_simple_shading.html)
与 [UsdPreviewSurface 规范](https://openusd.org/dev/spec_usdpreviewsurface.html)，不引入下载资产或生成视频。
